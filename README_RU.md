# Второй Мозг для Claude Code

[📖 Read in English](README.md)

> Система долгосрочной памяти для Claude Code + Obsidian.
> Vault знаний, который растёт с каждой сессией.

---

## Проблема

Claude Code — мощный инструмент, но у него амнезия. Каждая новая сессия начинается с чистого листа. Вы тратите 15–30 минут на объяснение того, что уже обсуждали вчера. За неделю — 2–3 часа впустую.

## Идея

Андрей Карпати в 2025 году описал паттерн [LLM Knowledge Bases](https://x.com/karpathy): вместо того чтобы загружать сырые документы в контекст каждый раз заново, LLM **компилирует** их в постоянную wiki один раз, а потом поддерживает её актуальной. Знания накапливаются — система умнеет с каждой итерацией.

Этот репозиторий — реализация этой идеи для Claude Code с Obsidian как интерфейсом.

## Как это работает

Два независимых пространства, связанных через `CLAUDE.md`:

```
~/Workspace/projects/dotfiles/              ← ваш код (обычный репозиторий)
    CLAUDE.md                     ← МОСТ: указывает на vault

~/Workspace/second-brain-vault/   ← Obsidian Vault (приватный репо)
    dotfiles/                     ← знания по проекту
        _PROJECT.md               ← что, зачем, текущий статус
        taskboard.md              ← задачи проекта
        architecture-map.md       ← карта кода (только code/mixed проекты)
        raw/                      ← сырые источники (конфиги, транскрипты)
        wiki/                     ← скомпилированные знания (пишет Claude)
            decision-*.md         ← записи решений (неизменяемые, ADR-lite)
        sessions/                 ← логи сессий
    00-system/                    ← карта vault и связи между проектами
    00-shared/                    ← кто вы: CRITICAL_FACTS.md + SOUL.md
```

При старте сессии Claude читает `CRITICAL_FACTS.md` + `_PROJECT.md` + `taskboard.md`
(~450 токенов) и сразу знает весь контекст. Для кодовых проектов также читает
`architecture-map.md` — карту маршрутов/модулей, которая заменяет сканирование репозитория.

## Быстрый старт

```bash
# 1. Клонируй репо
git clone https://github.com/dmitrax/second-brain-setup
cd second-brain-setup

# 2. Установка (создаёт vault + копирует команды в ~/.claude/)
bash install.sh

# 3. Заполни профиль — один раз
cd ~/Workspace/projects/any-folder && claude
> /brain-setup

# 4. Создай первый проект
mkdir ~/Workspace/projects/dotfiles && cd ~/Workspace/projects/dotfiles && claude
> /brain-init dotfiles

# 5. Работай. Сохраняй. Повторяй.
> /brain-save
```

## Команды

| Команда | Когда |
|---|---|
| `/brain-setup` | Один раз после установки — заполнить профиль |
| `/brain-init [название]` | Новый проект |
| `/brain-save` | Конец каждой сессии |
| `/brain-ingest raw/[файл]` | Обработать источник в wiki |
| `/brain-lint` | Аудит текущего проекта |
| `/brain-lint --all` | Полный аудит vault (раз в неделю) |

## Ключевые принципы

**Автономные проекты.** Каждый проект — самостоятельная папка. Удалить проект = удалить одну папку. Добавить = создать одну папку.

**AI-First заметки.** Каждая wiki-заметка содержит `## For future Claude` — инструкцию для читающего Claude: когда использовать эту заметку и ключевые факты. Паттерн взят из системы [Eugeniu Ghelbur](https://github.com/eugeniughelbur/obsidian-second-brain).

**Rewrite, не append.** При обработке нового источника Claude перезаписывает существующие заметки — обновляет факты, удаляет устаревшее. Vault не превращается в свалку.

**Граф знаний.** Claude создаёт `[[wikilinks]]` между заметками при каждом сохранении. Obsidian Graph View показывает как растёт ваша база знаний.

**Безопасность raw/.** Файлы в `raw/` считаются ненадёжным контентом. Claude никогда не следует инструкциям из сырых файлов — защита от prompt injection.

## Архитектура памяти

Четыре дома, и **один факт живёт ровно в одном** — скопированный не становится
находимее, копии расходятся, а протухшей копии доверяют ровно так же, как свежей.

| Память | Когда читается | Что держит |
|---|---|---|
| проектный `CLAUDE.md` | каждую сессию, автоматически, до того как тема известна | то, что **не** протухает |
| Obsidian vault | по требованию, через `_PROJECT.md` + grep | всё, что меняется |
| авто-память `~/.claude/projects/*/memory/` | при вспоминании, по релевантности | пользователя, а не проект |
| глобальный `~/.claude/CLAUDE.md` | каждую сессию **каждого** проекта | эту машину и этого человека, никогда не проект |

**Ничего выученного в проекте не пишется в глобальный `~/.claude/CLAUDE.md`** — ни правило,
ни урок, ни замер, каким бы общим он ни казался. У него самый широкий охват из четырёх и
самые слабые гарантии: `~/.claude/` не под контролем версий (ни диффа, ни отката), не
переезжает между машинами, и ни одна проверка этого пакета до него не достаёт. Урок,
который стоит хранить, идёт в vault — если он про работу, — или в сам пакет, если он про
поведение системы; оба версионируются и синхронизируются.

## Синхронизация между устройствами

Vault — просто папка с `.md` файлами. Git синхронизирует её между устройствами бесплатно. Obsidian Sync не нужен.

```bash
# Vault
cd ~/Workspace/second-brain-vault && git pull
# после /brain-save:
git add . && git commit -m "$(date +%Y-%m-%d)" && git push
```

Важно: используйте одинаковый путь к vault на всех устройствах (`~/Workspace/second-brain-vault/`).

## Версионирование

С v1.4.0 — semver (`MAJOR.MINOR.PATCH`). `PATCH` — багфиксы без нового поведения,
`MINOR` — новые обратно-совместимые фичи/правила, `MAJOR` — breaking changes со
скриптом миграции. Теги `v1.0`–`v1.3` остались под прежней грубой схемой
("v1.x = всё аддитивное") и не переразмечены задним числом.

```bash
# Обновить установленную систему после изменений
bash update.sh

# Какая версия реально стоит
bash ~/.claude/skills/second-brain/lib/brain.sh version
```
**Обновление с v1.0 → v1.1** (путь к vault изменился):
```bash
mv ~/Documents/second-brain-vault ~/Workspace/second-brain-vault
# Затем обновите строку Vault: в CLAUDE.md каждого проекта
```

## Changelog

### v1.8.0 — 2026-08-20

- **Гейт теперь спрашивает, есть ли сила у его собственных проверок.** `preflight.sh
  --mutate` по очереди вырезает каждую функцию в `lib/`, гоняет весь гейт и называет те,
  которые не защищены ничем. Написан потому, что гейт из 74 проверок был зелёным тем же
  утром, а мутация убрала охраняемое поведение у **восьми из них, и ни одна не
  покраснела** — число мерило присутствие проверок, а не их силу. Сейчас защищены все 38
  функций; режим — это 38 прогонов гейта и идёт минуты, сознательно.
- **Ворота релиза 2 и 3 меряются, а не удостоверяются.** `brain.sh release-check` гоняет
  линт по живому ваулту и показывает дельту, затем ищет лог сессии, датированный не раньше
  HEAD, в проекте со штампом той версии, которую HEAD описывает — обе половины, потому что
  лог сам по себе говорит, что сессия была, а штамп — что она была *на этом коде*.
  Добавлено после того, как ворота 3 объявила закрытыми сессия, написавшая код, который
  судила, — ровно то, что это условие запрещает дословно.
- **Obsidian CLI больше не пишет в vault вообще.** Один вызов `obsidian move` под
  guard'ом, адресованный через `path=` и проверенный чистым `git status` сразу после,
  записал `"alwaysUpdateLinks": true` в настройки самого ваулта, после чего GUI перецелил
  ссылки из устаревшего кэша в середину посторонних предложений — **8 мест в 6 файлах**,
  exit 0. Проверка, поставленная ПОСЛЕ вызова, не видит порчи, которая приходит позже,
  поэтому правило абсолютное. Переименование — `brain.sh rename`: сам перецеливает все
  формы ссылки, отказывается от имени, уже занятого в другом месте ваулта, и печатает,
  сколько цитат он намеренно оставил.
- **`/brain-save` отчитывается о том, что действительно сделал**, меряя рабочее дерево
  ваулта. До этого сохранение отработало **восемь шагов из двенадцати и отчиталось об
  успехе** — исчезли ровно те четыре, что не оставляют видимого вывода, а заметил это
  владелец по тому, что сейв прошёл быстро. Теперь каждый шаг печатает `ok`, `MISSING`
  (безусловный шаг без следа — ошибка) или `ANSWER` (условный шаг, на который надо
  ответить словами).
- **Три секции прозы `_PROJECT.md` ограничены независимо**, а не суммой: `Current state` —
  30 строк, список сессий — 5 записей, `For future Claude` — 20 строк. Суммарный бюджет
  переурегулировал то, чем уже управляли другие правила, и поэтому горел постоянно:
  замерено по всем ревизиям с момента его ввода — один проект был OVER в **66 из 96**.
  Предупреждение, срабатывающее два прогона из трёх, — не предупреждение.
- **Свежесть проекта меряет запись против работы, а не календарь.** Прежние «14 дней с
  `updated:`» сообщали, как недавно владелец решил чем-то заняться, — факт о приоритетах.
  Замер на живом ваулте: **7 находок, все шум.** Теперь сообщается обратное и редкое:
  лог сессии, которого `_PROJECT.md` не отражает. Проект со `status: reference` / `paused`
  / `archived` от проверки освобождён, и освобождение названо в выводе.
- **У decision-заметки появилась короткая форма.** Замер по ваулту: 286 заметок, медиана
  **68 строк, ни одной короче 20**, и 29 несут пустой раздел «Alternatives rejected». Один
  вес для решений любого размера означает, что решение на одну фразу либо раздувается под
  разделы, либо выдумывает для них содержание, — а худший исход это заметка, которую
  никто не написал, потому что форма тяжёлая. Форму выбирает один вопрос: были ли
  альтернативы, которые стоит записать?
- **Линт делит область и запечатывает по проекту.** `--project` / `--scope` значат, что
  прогон по одному проекту сравнивает и запечатывает только свою область, вместо того
  чтобы стирать находки другого проекта из baseline, общего для всех машин. `/brain-lint`
  к тому же пересобирает находки перед диффом, поэтому не может запечатать то, что сам же
  только что починил.
- **Новые команды библиотеки**, каждая закрывает шаг, который проза могла описать, но не
  могла разместить: `catalog` генерирует индекс заметок при каждом вызове — и никогда его
  не хранит, потому что сохранённый индекс это вторая копия знания — и показывает
  положение каждого решения; `connections-add` вставляет запись в начало своей секции и
  проверяет позицию, о которой отчитался (до этого замерено: **89 августовских записей под
  июльским заголовком**); `backfill-dates` восстанавливает даты закрытия из истории git для
  записей, которые `archive` иначе не смог бы унести никогда.
- **Гейт заявляет то, чего он не проверил.** Проверки, не сумевшие исполнить ветку на этой
  машине, выдают признание, которое собирается и печатается блоком «not verified by this
  run» — сознательно **без** влияния на код возврата: непокрытая ветка это не провал, а
  предупреждение, горящее на каждом обычном прогоне, перестают читать.
- **Язык делится по аудитории, а идентификаторы не переводятся никогда.** Всё, что репо
  публикует, — по-английски, включая вывод `lib/`: это данные, которые сессия читает,
  прежде чем написать фразу вокруг них на языке владельца ваулта. Ключ находки — то, что
  сравнивает baseline, поэтому переведённый ключ читался бы как одна находка появилась,
  а другая исчезла в одном прогоне.
- **`preflight.sh` вырос с 37 до 79 проверок.** Каждая кодирует случившийся инцидент, а
  новые проверяются негативно: копия ломается намеренно, и проверка обязана покраснеть.

**Обновление с v1.7.0 → v1.8.0:** запусти `update.sh`. Ничего не ломается — существующие
заметки, заголовки и форматы не тронуты, все новые правила аддитивны. Два изменения
поведения, о которых стоит знать: переименование теперь идёт через `brain.sh rename`, а не
через Obsidian CLI, и `/brain-save` заканчивается отчётом, чьи строки `MISSING` и `ANSWER`
ждут ответа.

### v1.7.0 — 2026-08-04

- **Исполняемый код уехал из промптов в `lib/brain.sh`.** Замер, из-за которого это
  случилось: 575 строк настоящего bash (`install`/`update`/`preflight`) — ни одного бага
  за всю историю проекта, против 288 строк code-блоков внутри промптов, где нашлись **все
  четыре** бага v1.4.3/v1.5.0. Код, который выглядит кодом, но не запускается, не
  тестируется и даже синтаксически не проверяется. Теперь guard — одна копия, которую все
  вызывают, плюс `vault-sync`, `stamp-field`, `version`, `archive` и `lint-diff`.
  `preflight` проверяет их **запуском** — ради этого вынос и делался.
- **Все команды синхронизируют vault до первой записи — и чтение тоже.** Несколько файлов
  vault'а это append-only реестры, которые правит каждая сессия на каждой машине, поэтому
  запись поверх устаревшего чекаута конфликтует по построению. Чтению это нужнее: на
  устаревшем чекауте `_PROJECT.md` и `taskboard.md` на месте, читаются и выглядят
  актуальными — сессия молча работает с состоянием «на момент прошлого визита на эту
  машину». Недоступный remote предупреждает и не мешает, конфликт останавливает запись.
- **Установленная система знает свою версию.** `install.sh`/`update.sh` пишут
  `lib/VERSION`, `brain.sh version` её читает, `/brain-init` подставляет реальное значение
  вместо хардкода, `/brain-save` перештамповывает при каждом сохранении. Замер до починки:
  8 проектов заявляли `1.3`, два — `1.5.0`, ни один — реально выпущенную версию.
- **Шаблоны frontmatter объявлены минимумом**, и шаг поиска локальных ключей проекта стоит
  **до** первой записи. У проекта могут быть ключи, о которых пакет знать не может; явный
  шаблон под рукой побеждает правило, прочитанное двести сообщений назад. Ключ переносится
  и проверяется машинно, значение выводится под конкретную запись.
- **`/brain-lint` получил пять шагов.** Step 0c объявляет неполный чекаут и запрещает
  печатать с него baseline. Step 4b свипает весь vault на голые `[[ссылки]]` к неуникальным
  именам — верная ссылка портится сама, как только другой проект займёт то же имя файла,
  поэтому шаг гоняется каждый раз, а не только для новых проектов. Step 4c меряет ссылки в
  заметках. Step 10b проверяет однородность ключей frontmatter внутри проекта. Step 12
  показывает **дельту** к прошлому прогону: сначала NEW, потом GONE, потом счёт
  припаркованного долга, который не надо разбирать заново.
- **Правило «минимум 2 wikilinks» отменено**, вместо него то, которое шаблон способен
  выполнить: обратная ссылка `[[../_PROJECT|_PROJECT]]` всегда, плюс ссылка на соседнюю
  заметку, когда действительно родственная существует. Прежний порог был невыполним для
  заметки, первой по своей теме, — он требовал либо вечного нарушения, либо выдуманной
  ссылки.
- **Code-блоки промптов обязаны быть переносимыми**: оболочка сессии на macOS — zsh, а имя
  команды не гарантирует инструмент (`#!/bin/bash` задаёт оболочку, а не `PATH`). Оба
  класса до правила падали молча и зелено.
- **Vault выкладывается целиком на каждой машине.** `sparse-checkout` оставляет
  отслеживаемые пути вне рабочего дерева, а изнутри любой проверки «файла нет» и «файл не
  выложен» — одно наблюдение. Замер: 93 битые ссылки, из которых 91 фантом, и три находки
  в общем baseline, ушедшие в GONE без того, чтобы кто-то их чинил.
- **`preflight.sh` вырос с 23 до 37 проверок.** Каждая кодирует случившийся инцидент;
  часть прогнана негативным тестом — намеренно сломанная копия обязана покраснеть.

**Обновление с v1.6.0 → v1.7.0:** запусти `update.sh` — он теперь ставит ещё и `lib/`.
Ничего не ломается: формат заметок не меняется. Если vault выложен через `sparse-checkout`,
линт скажет об этом и откажется печатать baseline, вместо того чтобы выдать частичный vault
за целый.

  файлов vault — реестры, в которые дописывает каждая сессия на каждой машине, поэтому
  запись поверх устаревшего checkout конфликтовала на push по построению. Недоступный
  remote предупреждает и не блокирует сохранение; конфликт посреди rebase останавливает
  запись целиком, чтобы маркеры не попали внутрь заметок.
- **Поиск по vault обязан объявлять тип паттерна** — `grep -F` для имён заметок и
  `[[wikilinks]]`, `grep -E` для альтернатив. Голый `grep -r` трактует паттерн как
  *basic* regex: он неверен в обе стороны и молчит в обеих. Замер на живом vault:
  литерал `[[architecture-map]]` без `-F` дал 304 файла против 17, а `docker|colima`
  без `-E` — 1 файл против 37. Дорогая форма — вторая: почти пустой результат читается
  как «в базе про это ничего нет», и сессия идёт дальше без своей же памяти.
- **`corrected-by:` помечает частично устаревшую decision-заметку** — когда решение в
  силе, но опорный факт в теле опровергнут. `status` и тело не трогаются: `superseded`
  ложно списал бы действующее правило. Маркер стоит в исправляемой заметке, а не только
  обратной ссылкой из новой — обратную ссылку не видит тот, кто ещё не нашёл коррекцию.
- **`status:` у decision-заметки бинарен** — ровно `accepted` / `superseded` /
  `deprecated`, без полумер вроде `partially-superseded-by`. Степень изменения живёт в
  теле новой заметки, и та обязана переописать весь актуальный охват, а не только дельту.
  Значение вне схемы невидимо для property-запросов; `/brain-lint` его ловит.
- **Порог размера `_PROJECT.md` считает только прозу** (~60 строк на `Current state`,
  `Последняя сессия`, `For future Claude`), а не длину файла. Секции-списки ссылок растут
  линейно от числа решений и правилу не противоречат — складывая их в общий размер,
  проверка выставляла аккуратный крупный проект худшим нарушителем, чем мелкий запущенный.
- **`preflight.sh` — исполняемые ворота релиза**, 23 проверки собственных правил плюс
  установка в чистый `$HOME`. Каждая проверка стоит на живом инциденте: три бага из
  четырёх в v1.4.3/v1.5.0 ловились однострочным grep, которого не существовало.
  Нужен Python с PyYAML (`python3 -m venv .venv && .venv/bin/pip install pyyaml`);
  `install.sh` его не ставит и не копирует, обещание «без внешних зависимостей» цело.
- **Скрипты репо держат планку bash 3.2** — macOS отдаёт его как `/bin/bash`. Без
  `mapfile`, `declare -A`, `${var^^}`. Это не стиль: `preflight.sh` использовал
  `mapfile`, из-за чего две проверки получали пустой вход и **печатали ✓, ни разу не
  выполнившись**, десять дней. Отсюда общее правило, теперь действующее во всех
  воротах: проверка обязана падать, когда её вход пуст или когда отсутствует нужный
  ей инструмент. Зелёное значит «выполнено и чисто», никогда «не выполнено».

**Обновление с v1.5.0 → v1.6.0:** запусти `update.sh`. Ничего не ломается — новые
правила добавляют проверки и шаги, формат заметок не меняется. Если у vault нет remote,
новый шаг синхронизации молча пропускает себя.

### v1.5.0 — 2026-07-22

- **`_obsidian_available()` теперь проверяет, *какой* vault открыт** — сверяет
  `obsidian vault info=name` с `basename "$VAULT"`, а не только exit code. Все пути CLI
  относительны активному vault, поэтому переключённый в GUI другой vault молча уводил
  записи туда — exit 0, без предупреждения. Ожидаемое имя выводится из пути к vault,
  не хардкодится.
- **Step 0b в `/brain-save` больше не использует `obsidian property:set`** — правит поле
  `updated:` напрямую. `property:set` пересобирает *весь* frontmatter: снимает кавычки
  (`"1.4.3"` → `1.4.3`), разворачивает инлайн-списки в блочные (`tags: [session]`) и
  переинтерпретирует числоподобные значения (`007` → `7` — потеря данных). Guard в
  `/brain-save` больше не нужен вовсе; в `/brain-lint` он остаётся для read-only запросов.
- **Supersession decision-заметок — теперь два поля**: `status: superseded` и
  `superseded-by: <файл>`. Прежняя однострочная форма `status: superseded-by: <файл>`
  была невалидным YAML (двойное двоеточие), из-за чего Obsidian вообще не мог прочитать
  frontmatter такой заметки. `/brain-lint` Step 10 теперь помечает legacy-форму.

**Обновление с v1.4.x → v1.5.0:** запусти `update.sh`. Существующие заметки с
однострочной формой `status: superseded-by:` продолжают работать как текст, но невидимы
для property-запросов — раздели их на два поля (`/brain-lint` их покажет).
